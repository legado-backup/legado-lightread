请为轻阅（LightRead）独立设计第二版精细的移动端交互原型。

一、任务背景

用户很喜欢微信读书的配色、干净的界面，以及进入正文后的阅读体验，希望轻阅达到同样成熟、细致的设计水平。请重点学习微信读书，结合京东读书作对照，并根据轻阅实际具备的功能设计。

已经有一版原型，现在希望由另一个 agent 独立做一版，供用户比较。你需要提出自己的布局、层级和交互判断，不要只给现有版本换颜色、改圆角或替换字体。

交付的是可实际操作的单文件 HTML 原型，不是静态展示页，也不是修改轻阅应用。所有应用源码、既有原型和调研材料都要保留。

三、上一版的设计概况

v3 采用浅冷灰背景、白色分组、小面积蓝色操作状态与较多留白。保留藏书、论文、书源、阅读记录、设置五个一级目的地。正文默认隐藏工具，轻点中间呼出；排版分为文字、配色、页面；阅读模式区分场景与带读；听书拥有完整播放器、迷你条和独立位置。

它已经具备真实的本地文字导入、翻页/滚动、排版与字体切换、笔记书签、阅读模式、本地保存、系统语音调用及无声节奏演示等交互。账号、WebDAV、在线 AI、远程书源和互传等服务依赖明确标为流程演示。

新版本需要在整体组织、阅读工具的易用性、听读衔接、视觉细节等方面形成有理由的独立方案。既可以保留合理做法，也可以重做；用实际体验说明改进，不为制造差异而改变熟悉的操作。

四、必须覆盖的功能

1. 全局结构与命名
保留轻阅实际需要的五个一级模块，梳理每个模块的二级、三级入口。按钮使用明确的动作名称，设置项显示当前值。不要照搬竞品的会员、金币、商城和运营任务。

2. 藏书
继续阅读、搜索、筛选、排序、网格/列表、书籍详情、书单、标签、添加书籍、删除与撤销。至少可真实导入 TXT；Markdown/HTML 可按能力支持。导入后能打开、阅读并保存位置。

3. 阅读与排版
正文、工具显隐、目录、书内搜索、进度、书签、笔记、选中文字后的复制/划线/写想法。支持翻页、按章滚动、连续滚动，以及适合屏幕宽度的单栏/双栏。字体、字号、行距、字距、边距、缩进、对齐、配色必须真实作用于正文，调整后维持文本位置附近。

4. 阅读模式
依据轻阅现有能力，覆盖夜读、护眼、墨水屏、大字、沉浸，以及自动阅读、打字机、歌词、点睛等。分清场景、版式与带读各自的职责。说明哪些模式互斥、哪些可以组合。必须能启动、调整、暂停、继续和退出，退出后恢复应恢复的偏好，不只显示一个选中状态。

5. 听书，重点打磨
完整播放器、播放/暂停、当前位置、章节目录、速度、音色与来源、定时关闭、本章结束停止、收起后的迷你播放器、返回原文。
阅读位置与听书位置分别管理：手动翻页不能偷偷改变朗读位置；可以回到听书处，也可以改听当前页面。切换语速或音色时要合理保留播放/暂停状态。
有可用系统语音时可真实朗读；没有时给出明确说明与恢复入口。无声节奏演示必须明确标识，不能把推进进度条称为真实播放。在线/离线服务未接入时如实标为流程演示。定时应真实到点停止，取消、暂停期间的计时规则要清楚。

6. 设置与同步
全局外观与正文主题分工清楚。覆盖阅读偏好、功能开关、账号/WebDAV、同步内容、同步阶段、失败重试、文件待补、断开、备份导入导出、AI 与网络配置的相关流程。凭据与密钥的同步须单独确认，不在原型中保存或发送真实凭据。

7. 论文、书源与阅读记录
覆盖论文阅读、原版/重排、目录或缩略图、笔记、翻译与助手入口；书源搜索、范围、结果、空结果、错误恢复；阅读时间、目标、日历和继续阅读。可以用原创 HTML 样稿代替完整 PDF 引擎，用明确标注的预置回答代替在线 AI，不虚构实验结果或历史统计。

8. 各种状态与文案
为加载、空状态、选中、禁用、保存成功、删除撤销、错误重试、播放暂停、定时结束、同步失败等设计完整反馈。每种状态告诉用户发生了什么，以及接下来能做什么。重要状态不能只用颜色表达。

五、视觉与交互要求

- 主要学习微信读书：克制的颜色、清晰的文字层级、舒服的留白、稳定的操作位置、按需出现的工具，以及长时间阅读的舒适感。
- 提出你自己的具体方案，不做营销落地页，不画假手机边框或假系统栏。
- 正文、导航、设置、播放器使用一致的设计语言；夜间阅读时，工具和面板也应适配，避免突然出现刺眼的白色面板。
- 字体预览必须展示实际字形。尽量内嵌可合法分发的字体子集，保留许可证，确保单文件在手机上稳定显示。
- 操作适合触屏，主要点击目标不小于 44px；处理底部安全区、长文字、键盘弹出、焦点、返回和关闭。
- 每个可点击入口都要有实际行为或清楚的流程演示。不要用通用“敬请期待”弹窗填充功能。
- 服务流程的演示标识要让体验者看得懂，但不要把实现细节塞满产品界面。
